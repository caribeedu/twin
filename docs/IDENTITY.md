# Identity

This document explains what Twin *is* — stable identity, category
positioning, core claim, durable principles and how Twin should be
spoken about. These should survive replacement of models, stores,
protocols and interfaces.

It does not describe implementation, architecture, roadmap or the
research cycle. Those live in [ARCHITECTURE.md](ARCHITECTURE.md),
[PRODUCT.md](PRODUCT.md), [ROADMAP.md](ROADMAP.md) and
[RESEARCH.md](RESEARCH.md). What “understanding” and situation models
are: [COGNITION.md](COGNITION.md). Vocabulary: [GLOSSARY.md](GLOSSARY.md).
Destination narrative: [README](../README.md).

---

## What Twin Is

Twin is an attempt to define a new layer of AI infrastructure.

Its identity is not derived from a particular language model, retrieval
strategy, database, protocol or user interface.

Its identity is defined by one objective:

> **Form, preserve and evolve computational understanding.**

Everything else is an implementation decision.

---

## Core Claim and Value Proposition

Twin should not compete on memory, RAG, knowledge graphs or agents
individually.

Its claim is:

> Twin forms reusable understanding from distributed observations.

Memory, graphs, retrieval and agents are implementation techniques — not
the product.

**Value proposition:** every AI starts from zero. Twin enables authorized
AI systems to start from an evolving understanding instead.

## The Unit of Value

Most AI systems produce answers, retrieved documents, summaries, plans
or generated text.

Twin’s primary output is **understanding**: a reusable semantic
interpretation of reality that can survive beyond a single conversation,
model or application ([COGNITION.md](COGNITION.md)).

If Twin stores or retrieves information without increasing understanding,
it has failed. Understanding is the project’s fundamental unit of value.

---

## Positioning — Not These Categories

Twin should not be positioned as:

- another RAG framework;
- another agent framework;
- another knowledge graph;
- another personal memory system.

Those optimize retrieval, execution, structure or convenience. Twin is
**cognitive infrastructure** that transforms distributed observations
into reusable understanding.

Memory, graphs, retrieval, reflection and agents are supporting
mechanisms. The product is computational understanding.

Twin is not *defined by* memory, graphs, agents, context engineering or
any individual model:

- memory exists to preserve understanding;
- graphs organize relationships that contribute to understanding;
- agents consume understanding;
- context engineering delivers understanding;
- models are replaceable reasoning components that process understanding.

## Design Principles

These principles should outlive individual implementations. When a
feature conflicts with them, reconsider the feature before changing the
principles.

- **Human-first, not model-first.**
- **Understanding before memory.**
- **Reflection before durable knowledge.**
- **Evidence before belief.**
- **Judgment separate from facts.**
- **Privacy before reasoning.**
- **Local-first by default.**
- **Exportability over lock-in.**
- **Model independence.**
- **Replaceable infrastructure** — identity before technology.
- **Demonstrable capabilities over architectural complexity.**
- **Benchmarks over anecdotes** — [RESEARCH.md](RESEARCH.md#benchmarks).

How several apply in the running system: [ARCHITECTURE.md](ARCHITECTURE.md).

---

## Identity Before Technology

Twin should preserve its identity before preserving any technology.

Future versions may replace graph databases, vector databases, LLM
providers, execution models, protocols or memory representations.

None of those changes should alter the project’s identity.

The only enduring question is:

> Does this improve computational understanding?

---

## Evidence Before Belief

Twin deliberately rejects architectural dogma.

Concepts are adopted because experiments suggest they improve
understanding — not because they are fashionable. Concepts should be
removed when evidence shows they no longer contribute.

Changing direction after stronger evidence is expected behavior. The
engineering-research cycle is in [RESEARCH.md](RESEARCH.md#method).

---

## Human-Centered Cognition

Twin does not replace human judgment. Its purpose is to strengthen it.

Understanding should remain inspectable, explainable, evidence-backed,
revisable and governed by the user.

Augmentation — not substitution — is the guiding principle.

---

## Independence

Twin should remain independent from any AI vendor, interface, assistant,
protocol or deployment model.

Its cognitive continuity should outlive every individual technology it
integrates with.

---

## How Twin Should Be Spoken About

Lead with outcomes and demonstrations, not architecture jargon
(knowledge graphs, embeddings, MCP, observers).

Example: a user asks about a project in a fresh conversation. The
assistant answers with a synthesized understanding built from Slack,
GitHub and previous events — without the user re-explaining anything.
Only then explain how Twin achieved it.

### Don’t Sell Features

Demonstrate capabilities instead — cross-source understanding, situation
synthesis, preference evolution, decision revision, context continuity.

Prefer publishing engineering articles, reproducible benchmarks,
architecture notes and experimental results over marketing. Become the
reference for the *problem* before becoming the largest implementation.

---

## Identity Is Measured by Behavior

Twin should be recognized by observable behavior rather than internal
architecture.

People should say:

> “It already understands what has been happening.”

— or —

> “The AI already understood what happened.”

— not “It uses graphs,” “It retrieved the right documents,” or “It
injects context.”

Mechanisms are implementation details. Behavior is identity.

---

## The Long-Term Identity

Memory, reflection, judgment and agency may evolve over time.

The identity should not.

Twin exists to progressively build, maintain and refine computational
understanding that remains under human authority and can be shared with
any authorized intelligence.

Everything else is secondary.
